## ADR-141 · Patch keamanan Hono 4.13.22 di `apps/api`; `figlet` (CLI HeroUI Pro) dicatat, tidak di-override — diterima · 2026-11-26

**Konteks:** Sesudah ADR-140, `pnpm audit --prod` masih memuat dua kelompok advisori di luar Next.
- `hono` 4.13.13 (Worker Jawab `apps/api`; tanpa route publik sendiri, dijangkau publik lewat proksi web `/api/jawab`, ADR-064): GHSA-4m76-xfj5-7975 (`mount()` melewati middleware), GHSA-h7mg-cq63-vhpq (`RegExpRouter` melewatkan middleware wildcard; mengenai `SmartRouter` bawaan), GHSA-46wx-v44x-9hh2 (`csrf()`), GHSA-4h7h-rv7c-7m2v (`validator('form')` multipart), semuanya moderate, ditambah GHSA-3gg2-335m-rxc6 (helper `css`, low). Semuanya ditambal di 4.13.16. Catatan rilis 4.13.18 menambal isu lanjutan pada `validator`, `bodyLimit`, `mount` dan `serveStatic`.
- `figlet` 1.11.0 (GHSA-62ch-8vmq-8xm7, high; DoS saat `text()`/`textSync()` dengan `whitespaceBreak` dan `width` dari input tak tepercaya): dependensi langsung CLI `heroui-pro` 1.0.0-beta.14 (versi terbaru CLI), yang dibawa `@heroui-pro/react` 1.0.0-beta.10.

Surau hanya memakai `new Hono()`, `app.get`/`app.post` (`/health`, `/jawab/status`, `/jawab`, semuanya statis tanpa middleware), `app.notFound`, `app.onError` dan `hono/streaming`; tidak ada `mount`, `csrf`, `validator`, `bodyLimit`, `serveStatic`, `hono/css`, `hono/jwt` maupun `basicAuth`. Jadi jalur eksploit tidak terjangkau sekarang, kecuali kemungkinan kecil pada perbaikan router.

**Keputusan:**
1. Catalog `hono` 4.13.13 → **4.13.22** (2026-11-25 00:06 UTC, lolos `minimumReleaseAge`). Ini patch dalam 4.x; perubahan perilaku 4.13.16–4.13.22 (pola `RegExpRouter` yang cocok dengan string kosong ditolak, `mount` lebih ketat, `basicAuth` memvalidasi tipe, JWT Base64URL kanonik) tidak mengenai rute Surau. Hono 5 (rc) tidak dipakai.
2. `figlet` **tidak** di-override (mitigasi dan bukti di ADR-003: CLI hanya memanggil `textSync("HeroUI Pro")` tanpa opsi; larangan mengaktifkan `whitespaceBreak` tetap). Ia tidak masuk bundel runtime (`grep` di `dist` `@heroui-pro/react` tidak menemukannya), hanya dipakai CLI saat instalasi atau pemakaian lokal, dan masukannya tidak pernah berasal dari pengguna. Override `figlet >=1.11.3` tanpa uji CLI berisiko memutus postinstall Pro demi risiko yang tidak terjangkau. Advisori ini menutup sendiri saat `heroui-pro` menaikkan figlet atau saat HeroUI Pro dinaikkan (`@heroui-pro/react` 1.0.1 stabil tersedia 2026-11-24; pindah beta → stabil diputuskan terpisah).

**Ditolak:** Hono 5.0.0-rc; `pnpm.overrides` untuk figlet (lihat poin 2); menaikkan HeroUI Pro ke 1.0.1 di sesi ini (lompatan beta → stabil, perlu tinjauan komponen tersendiri).
**Konsekuensi:** `pnpm audit --prod` hanya memuat `figlet` (high, hanya CLI). Lockfile hanya berubah pada `hono`.
**Tinjau ulang bila:** `heroui-pro` CLI merilis versi dengan figlet ≥1.11.3, HeroUI Pro dinaikkan ke 1.x stabil, `apps/api` mulai memakai `mount`/`validator`/`csrf`/`bodyLimit`, atau Hono 5 stabil.
