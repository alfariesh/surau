## ADR-136 · Build korpus Ihya dari `main` memakai Intisari pilot X15b sampai X15c digabung atau dibuang — diterima · 2026-11-26

**Konteks:**
- T-35 (build staging patch ayat X29, mesin agent) menemukan bahwa `data/build/llm/intisari` sudah berisi hasil X15c. Hasil itu dibuat dengan prompt `digest-section@3` dan `digest-merge@2` dari cabang `sesi/x15c-intisari-penuh`, yang belum digabung dan diparkir oleh ADR-135. Kode di `main` masih `digest-section@2` dan `digest-merge@1`, sehingga `Freshness` menganggap ke-463 hasil basi.
- Akibatnya `pnpm ingest ihya` biasa lolos semua gerbang, tetapi keluar dengan **Intisari 0** dan **audio 0**, padahal produksi `ihya-v9` menayangkan 19 Intisari (119 gagasan) dan audionya. Gerbang Intisari tidak punya batas bawah, jadi regresi ini tidak terlihat sebagai ✗. Build tanpa patch ayat juga menghasilkan 0, jadi penyebabnya bukan X29.
- Intisari produksi tersimpan utuh di `data/build/llm/intisari-pilot-x15b-cadangan-2026-10-27`, dengan prompt `@2` dan `@1`. Daftar tarik ADR-127 tetap mengenainya karena kunci `digest_created_at` 100007/100017 ada di cadangan itu.
- Kode ingest membaca Intisari dari path tetap `join(paths.llm, "intisari")`, tanpa opsi untuk memilih folder lain.

**Keputusan:**
1. Sampai X15c digabung ke `main` atau dibuang, **setiap build Ihya dari `main` memakai Intisari pilot X15b**, yaitu Intisari yang sedang tayang. Hasil X15c tidak dihapus, karena itu hasil batch berbayar.
2. Caranya adalah penukaran folder sementara di mesin agent, dari root repo:
   1. Salin `data/build/llm/intisari` ke scratchpad (`cp -a`).
   2. `mv data/build/llm/intisari data/build/llm/intisari-x15c-sementara`.
   3. `cp -a data/build/llm/intisari-pilot-x15b-cadangan-2026-10-27 data/build/llm/intisari`.
   4. `pnpm ingest ihya`.
   5. Hapus salinan pilot, kembalikan folder X15c dengan `mv`, lalu `diff -rq` terhadap salinan scratchpad harus kosong.

   Hasil build harus memuat Intisari 19/313 node dan 119 gagasan. Bila angkanya lain, build tidak boleh dimuat.
3. **Promote X29 tetap membangun ulang.** `ihya-v9` sedang melayani produksi, jadi promote butuh versi baru (`corpusVersion` `ihya-v10`) dan build baru dengan langkah 2. Build staging 2026-11-26 diarsipkan sebagai pembanding hitungan di `data/build/arsip/x29-staging-2026-11-26/` (tidak masuk git, sha `13c66330…`).
4. **Pemicu perbaikan permanen**, yang mana pun lebih dulu: X15c dilanjutkan (prompt `@3`/`@2` digabung, dan cadangan pilot tidak lagi dipakai), atau kitab kedua (X31a) membutuhkan Intisari per karya. Perbaikannya adalah path Intisari per karya lewat `WorkConfig` (misalnya `intisariDir`), ditambah gerbang batas bawah Intisari ("tidak berkurang dari korpus produksi tanpa izin") supaya regresi senyap seperti ini menjadi ✗. Sampai salah satu pemicu terjadi, langkah 2 dipakai.

**Akibat:**
- Build X31a (multi-kitab) dan X24 yang memuat Ihya wajib memakai langkah 2. X31a juga menimpa `surau-corpus-staging` yang sedang menunggu izin promote X29. Karena itu urutannya: promote X29 dulu, atau X31a membangun ulang staging X29 sesudahnya.
- Penyimpangan dari X29 langkah 6.2 (cukup `pnpm ingest ihya`) dicatat terbuka di file sesi X29.
