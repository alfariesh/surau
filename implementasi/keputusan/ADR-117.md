## ADR-117 · Catatan keputusan dan jurnal dipecah: satu file per ADR, arsip log per bulan — diterima · 2026-10-28

**Konteks:** `implementasi/KEPUTUSAN.md` sudah 3.111 baris (±594 KB, 116 ADR) dan `implementasi/LOG.md` 1.043 baris (±149 KB). Agent tidak bisa membacanya sekaligus, dan sesi paralel sering bentrok di file yang sama: nomor ADR pernah kembar (audit manajemen proyek 2026-10-28).

**Keputusan:**
1. Setiap ADR pindah ke file sendiri `implementasi/keputusan/ADR-NNN.md`. Isinya dipindah apa adanya (judul, tanggal, status, dan isi). Satu-satunya perubahan: tautan relatif di dalam isi ADR diberi awalan `../` karena file pindah satu folder lebih dalam.
2. `implementasi/KEPUTUSAN.md` menjadi indeks: tabel nomor, judul, status, tanggal, dan tautan ke file ADR, plus cara menambah ADR baru (satu file baru dan satu baris indeks). Bagian "Keputusan yang menunggu pemilik" tetap di indeks.
3. `implementasi/LOG.md` tetap memuat bulan berjalan. Entri bulan sebelumnya dipindah ke `implementasi/log/YYYY-MM.md`. Per 2026-10-28 semua entri masih Oktober 2026, jadi belum ada berkas arsip; aturan pindahnya ditulis di `LOG.md`.
4. Rujukan ke kedua file diperbarui (`CLAUDE.md`, `implementasi/README.md`, skill `sesi`). Path `KEPUTUSAN.md` dan `LOG.md` tetap ada sebagai indeks dan jurnal, jadi rujukan lama ke path itu tidak rusak.

**Ditolak:**
- Menulis ulang isi ADR agar lebih ringkas. Ditolak karena keputusan tidak boleh berubah diam-diam; ADR dipindah, bukan disunting.
- Satu file per tahun atau per bulan untuk ADR. Ditolak karena tidak mengurangi tabrakan nomor; satu file per ADR membuat sesi paralel menulis berkas yang berbeda.
- Memindahkan `KEPUTUSAN.md` dan `LOG.md` dari path lama. Ditolak karena banyak rujukan dan tautan jangkar (`KEPUTUSAN.md#keputusan-yang-menunggu-pemilik`) bergantung pada path itu.

**Konsekuensi:** mencari ADR sekarang membuka `implementasi/keputusan/ADR-NNN.md` lewat indeks. Nomor baru dipilih dari `origin/main`, dan satu ADR baru selalu satu berkas baru. Batasnya: setiap ADR baru tetap menambah satu baris ke tabel indeks yang sama, jadi dua sesi paralel bisa tetap konflik di tabel itu saat merge. Konflik itu mudah diselesaikan dengan menggabungkan kedua baris. Gabungan isi berkas ADR identik dengan `KEPUTUSAN.md` sebelum dipecah, kecuali awalan `../` pada tautan relatif.

**Tinjau ulang bila:** berkas ADR tumbuh terlalu besar untuk dibaca sekali (lebih dari satu layar), atau log bulanan menjadi sulit dicari.
