## ADR-137 · Korpus banyak kitab: satu build gabungan `kitab-v10`, hasil LLM dan Intisari per kitab, reset penuh tetap — diterima · 2026-11-26

**Konteks:**
- Gelombang 1 (ADR-135) menambah kitab ke korpus D1 yang selama ini hanya berisi Ihya. Skema dan URL sudah mendukung banyak karya (ADR-029), tetapi alat ingest membangun satu kitab per build, `0000-reset.sql` mengosongkan seluruh DB, dan nama versi korpus berawalan `ihya-`.
- `tools/ingest/README.md` dan ARSITEKTUR-TEKNIS §ingest mencatat "kitab kedua butuh reset per edisi".
- ADR-136 butir 4 menyebut kitab kedua (X31a) sebagai pemicu perbaikan permanen folder Intisari: path per kitab ditambah gerbang batas bawah Intisari.

**Keputusan:**
1. **Satu build berisi semua kitab.** `pnpm ingest korpus` membangun setiap kitab sendiri-sendiri, dengan sumber, peta ID, sidik teks, gerbang, dan laporan per kitab. Baris semua kitab lalu digabung menjadi satu `.sqlite` dan satu set SQL.
   - Tabel bersama dibangun sekali: tabel Qur'an, `term_stat` (dari indeks gabungan), dan `meta`.
   - Baris yang sama di beberapa kitab digabung tanpa duplikat (`author`, `glossary_term` berkunci `(term_key, lang)`). Kunci yang sama dengan isi berbeda = build gagal. Apakah glosarium milik korpus atau per kitab diputuskan di X31b, sebelum Bidayah punya Intisari.
   - `--terima-teks-berubah` dengan ID di luar semua edisi build = galat. Revisi X08 milik kitab yang tidak ikut build dicatat jumlahnya di laporan.
   - Invarian korpus baru: ID karya, ID edisi, slug, peta ID, dan awalan laporan unik per kitab.
   - `meta.source_hash` untuk satu kitab tetap `sha256:<sumber>`. Untuk beberapa kitab bentuknya `slug=sha256:…;…`, dan `corpus:qa` memeriksa bagian milik kitabnya.
2. **Versi korpus milik build, bukan kitab.** `CorpusConfig` (`tools/ingest/src/works/index.ts`) menyimpan versi `kitab-v10` (DB produksi `surau-corpus-kitab-v10`). Penomoran melanjutkan `ihya-v9`. Awalan `kitab` dipilih karena awalan `surau` menghasilkan nama janggal `surau-corpus-surau-v10`. `WorkConfig` kehilangan `corpusVersion` dan `output`.
3. **Reset penuh tetap dipakai (menyimpang dari catatan "reset per edisi").** Setiap build memuat semua kitab, jadi memuat ulang staging atau DB produksi baru dari nol tetap menghasilkan korpus utuh. Reset per edisi baru perlu bila kelak satu kitab dimuat terpisah tanpa build penuh; itu tidak direncanakan. README ingest dan ARSITEKTUR-TEKNIS diperbarui.
4. **Hasil LLM per kitab.** `WorkConfig.llm = { dir, intisari }`, relatif ke `data/build/llm`. Kitab tanpa entri dibangun tanpa terjemahan, ringkasan, dan Intisari (gerbang `llmCoverage` 0).
   - Ihya memakai `dir: "."` (tata letak lama) dan `intisari: "intisari-pilot-x15b-cadangan-2026-10-27"`. Ini Intisari yang tayang di `ihya-v9` (ADR-136), sehingga penukaran folder di ADR-136 butir 2 tidak diperlukan lagi.
   - Revisi terjemahan manusia (X08) disaring per edisi. Metadata revisinya dicatat sekali di `meta` korpus.
5. **Batas bawah Intisari:** `expect.minDigests` (Ihya 19). Build yang memuat Intisari lebih sedikit gagal, sehingga regresi senyap ADR-136 kini menjadi ✗.
6. **Kitab yang belum siap tidak ikut promote.** `corpus:promote` menolak build yang memuat kitab berstatus selain `tayang` di `data/kitab/ledger.yaml`, kecuali dengan `--kitab-baru`. Bila promote produksi terjadi sebelum kitab baru lolos "Definisi selesai" X31, bangun dengan `--kitab ihya`. Bila build sebagian itu sudah memakai nama `kitab-v10`, build penuh berikutnya naik versi (`kitab-v11`), karena promote menolak memuat ulang DB produksi. `/kitab` hanya menampilkan kitab yang ada di korpus. Rincian atribusi di `/lisensi` (statis) baru ditambahkan saat kitab tayang (X31b).
7. **Pendukung sumber.** Berkas Shamela tanpa kolom `is_deleted` (12718, 11371) dan dengan kolom `part` kosong (kitab satu jilid → juz 1, ADR-029) dibaca apa adanya. Gerbang "Halaman per juz" tetap menangkap kitab berjilid yang `part`-nya hilang.
8. **Alat per kitab.** `corpus:qa --kitab <slug>` membandingkan baris milik kitab itu saja (karya, edisi, pengarang, halaman sampel, dan bagian `source_hash`-nya). Alat batch LLM (`pnpm llm`, `pnpm llm intisari`) dan alat audio masih khusus Ihya; menjadikannya per kitab dipindah ke X31b langkah 1, karena baru dibutuhkan saat batch Bidayah.

**Alternatif ditolak:**
- *DB D1 per kitab:* binding `CORPUS_DB` tunggal dipakai web, MCP, dan API. Banyak binding atau DB berarti Cari lintas kitab harus menggabungkan hasil di Worker.
- *Reset per edisi sekarang:* menambah jalur muat parsial yang belum dibutuhkan dan lebih sulit diuji.
- *Menukar folder Intisari secara manual (ADR-136 butir 2) selamanya:* rawan lupa; konfigurasi per kitab ditambah gerbang batas bawah lebih aman.

**Dampak:**
- Build pertama `kitab-v10` berisi Ihya (dengan patch ayat X29) dan Bidayah, dibangun di mesin agent (ADR-135 butir 5).
- `pnpm ingest ihya` tetap diterima sebagai nama lama dan kini membangun korpus semua kitab.
- Tes lokal baru `tools/ingest/test/multi-kitab.test.ts` membangun Ihya + Bidayah dari sumber lokal dan memastikan ID Ihya tetap sama.

**Tinjau ulang bila:** jumlah kitab membuat build penuh atau muat D1 terlalu lama (lebih dari beberapa menit), atau satu kitab perlu dimuat tanpa membangun yang lain.
